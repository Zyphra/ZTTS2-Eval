# ARCHITECTURE — ZTTS2-Eval

A structural map of this repository: what exists, where it lives, and how the pieces connect.
This is a reference document — it describes the codebase, it does not prescribe changes.

## What this project is

**ZTTS2-Eval** — a multilingual, in-the-wild zero-shot text-to-speech (TTS)
evaluation benchmark. The pipeline is **prepare data → generate audio (TTS models)
→ score**. Core metrics:

- **WER/CER** — ASR transcription routed per language (Qwen3-ASR for `zh ko th vi hi fa`,
  Whisper-large-v3 with forced language otherwise, when `ASR_ROUTING=1`) + `jiwer`.
- **Speaker similarity** — ReDimNet embeddings, cosine (voice cloning fidelity).
- **Audio quality** — MSR-UTMOS (sarulab-speech SFI HuBERT).
- **Distributional prosody** (optional) — char/s distance, MPM span, TTSDS2 Pitch,
  and DS-WED diversity.

A stdlib web explorer browses the resulting scores.

### Environment
- Python **3.10–3.12** in `.venv`, managed by **uv**.
- Dependencies in `pyproject.toml` + `uv.lock`. Optional extras: `--extra scorers`
  (DS-WED + MSR-UTMOS), `--extra viz` (matplotlib/scipy), `--extra omni`
  (vllm-omni from git), `--extra gemini` / `elevenlabs` / `cartesia` / `inworld`
  (hosted-provider clients).
- CUDA 12.9 pinned wheels; `transformers<5.9` pin for vLLM-Omni compatibility.
- Shell scripts use Kaldi-style `utils/parse_options.sh` for `--name value` parsing
  and prefer `.venv/bin/python` when present (`PY=.venv/bin/python` else `python`).

### Git tracking state
- All source is tracked: `pyproject.toml`, `uv.lock`, the `run_generate_*.sh` /
  `run_infer_*.sh` entry points, `scripts/**` (`.py` + `.sh`, incl. `results_doc/`),
  `utils/*.py` + `*.sh`, `explorer/`, `docs/`, `assets/`, and the top-level reports.
- The `data/` metadata is tracked; the prompt wavs (`data/{zero_shot,zero_shot_voxblink}/<lang>/waveform/`)
  are gitignored and fetched from the Hugging Face dataset `Zyphra/ZTTS2-Eval` by
  `scripts/download_data.py`. The VoxBlink2 selection
  provenance is kept (`data/zero_shot_voxblink/_stage_a/manifest.tsv`), and
  `_msr_utmos_cache.tsv` is tracked too — it is the shipped MSR-UTMOS binning cache
  the eval scripts read. Only the `_stage_a/*_to_chmod.txt` lists are gitignored
  prep byproducts (regenerated by the stage A/B scripts).
- `.gitignore` excludes the venvs, caches (`__pycache__/`,
  `scripts/results_doc/_cache/`), logs, `results/` (except the committed GT score
  baselines), `third_party/`, and the VoxBlink2 prep byproducts noted above. See
  `.gitignore` for the authoritative list.

## Entry points (root `*.sh`)

### Generation → `results/<model>/<task>/<lang>/wavs/`
- **`run_generate_zonos2.sh`** → starts/stops a Zonos2 Mini-SGLang server via
  `scripts/serve_zonos2.sh` (`python -m zonos2`, from the `ZONOS2_HOME` checkout),
  then runs `scripts/generate_zonos2.py` (`POST /tts/generate`). Pass `--server URL`
  to reuse an external server instead. `--accurate_mode {true|false}` = stable vs
  expressive.
- **`run_generate_omni.sh`** → starts/stops a vLLM-Omni server via
  `scripts/serve_omni.sh`, then runs `scripts/generate_omni.py`
  (`POST /v1/audio/speech`). Inline model registry: qwen3-tts, cosyvoice3, voxcpm2,
  voxtral-tts, moss-tts-nano, fish-s2-pro, etc.
- **Hosted providers**: `run_generate_gemini.sh`, `run_generate_elevenlabs.sh`
  (+ `_clone`), `run_generate_cartesia.sh`, `run_generate_inworld.sh` →
  `scripts/generate_<provider>.py`. Each reads its API key from an env var.
- **`run_generate_{omni,zonos2,gemini}_voxblink.sh`** → variants targeting the
  `zero_shot_voxblink` task.

### Evaluation → scores written next to the wavs
- **`run_infer_zonos2_eval.sh`** → starts Qwen3-ASR (plus Whisper-large-v3 when `ASR_ROUTING=1` / `WHISPER_GPU` is set) via `scripts/serve_asr.sh`,
  then runs WER (`scripts/run_score_wer.sh` → `utils/run_wer.py`), speaker
  similarity (`scripts/eval_speaker_similarity.py`), and MSR-UTMOS
  (`utils/score_msr_utmos.py`). Reads `DECODE_DIR`.
- **`run_infer_voxblink_eval.sh`** → the same metric set for `zero_shot_voxblink`.

## `scripts/`

**Generation clients** (pure HTTP / SDK): `generate_zonos2.py`, `generate_omni.py`,
`generate_gemini.py`, `generate_elevenlabs.py` (+ `_clone`), `generate_cartesia.py`,
`generate_inworld.py`.

**Scoring drivers:**
- `eval_speaker_similarity.py` — ReDimNet via torch.hub; cosine sim → `spk_simi_scores.txt`.
- `utils/score_msr_utmos.py` — MSR-UTMOS MOS predictor → `msr_utmos_scores.txt` (the
  canonical scorer wired into `run_infer_*` and `run_gt_zero_shot.sh`).

**Data preparation:** `download_data.py` (fetches the released prompt audio from the Hugging Face Hub), `prepare_fleurs_r.py` (builds `zero_shot/` from
google/fleurs-r, max-out sample per language), `build_voxblink2_enriched.py`
(rebuilds the enriched candidate pool from xtx + transcript artifacts),
`prepare_voxblink2_eval_stage_a.py` (select candidates),
`prepare_voxblink2_eval_stage_b.py` (MSR-UTMOS stratified sample, round-robin across
5 bins up to ~1500/lang),
`extract_voxblink_gt.py`. The VoxBlink2 prep reads a local audio tree via
`VOXBLINK2_AUDIO_ROOT` and an enriched candidate pool via `VOXBLINK2_ENRICHED`.

**Aggregation / plotting:** `plot_dswed_dists.py`,
`speaking_rate_dist.py`, and `plot_ttsds_pitch_ridgeline.py` (renders the
mean-F0 distributions from `assets/plots/ttsds_pitch_ridgeline_data.npz`).

**Reliability plates:** `tufte_common.py` (shared loader — reconstructs exact
per-utterance edit counts from `wav_res_ref_text.wer.raw` using `run_wer.py`'s
tokenization, and resolves a "series" by language/set/model/regex) feeds four
edit-distance survival/reliability plotters — `tufte_p99.py`,
`tufte_survival_overlay.py`, `tufte_survival_smallmultiples.py`,
`tufte_slopegraph.py`. `run_reliability.sh` renders the nine plates
(`assets/plots/reliability_*.png`, over the FLEURS-R GT, VoxBlink2 GT, and an
ASR-backend view) and `build_reliability_gallery.py` embeds them into the
self-contained `assets/reliability_gallery.html`. `run_reliability.sh` runs as a
late step of `results_doc/run.sh` (the run ends with the snapshot publish).

**Run wrappers (`.sh`):** `run_score_wer.sh`, `run_dswed_omni.sh`,
`run_full_zonos2_generic.sh`,
`run_ttsds_pitch.sh` (+ `_all_langs`), `setup_ttsds_env.sh`, `wer_groundtruth.sh`.

**Servers (sourced, not executed):** `serve_asr.sh` (`start/stop_asr_server`,
env `ASR_*`), `serve_omni.sh` (`start/stop_omni_server`, env `OMNI_*`).

**`scripts/coreset/`** — coreset panels (offline, CPU-only; reads the per-utterance
scores already in `results/` and never regenerates audio). `build_matrix.py` assembles the
system × item matrix (`assets/coreset/matrix_<set>.npz`; `--verify` reproduces the
published RESULTS tables from it), `denoise.py` low-rank-shrinks item fingerprints,
`panel_select.py` holds the ten selectors + coverage quotas, `validate.py` /
`validate_delta.py` run leave-family-out and matched-pair power validation,
`export_panel.py` writes a panel as a runnable `data/<task>/` directory, `score_panel.py`
turns a panel run into a weighted estimate of the full score, `run.sh` drives the lot.
`scripts/repair_wer_raw.py` (repo root of `scripts/`) repairs `.wer.raw` records split by
tabs/newlines in the ASR hypothesis — the failure that leaves a footerless `.wer` and makes
aggregators silently drop a leaf. See `docs/coreset.md`.

**`scripts/results_doc/`** — report pipeline: `build_results.py`
(→ `_cache/results_snapshot.json`), `build_perbin.py`, `build_perlen*.py`,
`plot_*.py`, `gen_md.py`
(→ RESULTS_CURRENT.md, model-agnostic), `run.sh`. The pipeline reads from a
populated `results/` tree; the `_cache/` snapshot is gitignored.

## `utils/`

`utils/` is an importable package (`utils/__init__.py`); scripts add the repo root
to `sys.path` and `from utils.X import ...`.

- **Shared parsers:** `scp.py` (`load_scp`, `load_scp_items`, `load_text`);
  `per_uid.py` (`parse_wer`, `parse_spk`, `parse_score_path`, `load_leaf`) — the
  per-utterance score-file parsers, stdlib-only so `explorer/serve.py` and the coreset
  tooling share one implementation. Every parser returns `{}` for a missing file, because
  partial leaves are normal.
- **WER:** `run_wer.py` (Qwen3-ASR / Whisper client + jiwer; env `ASR_BASE_URL`/`ASR_MODEL`/
  `ASR_CONCURRENCY`, routing via `WHISPER_BASE_URL`/`QWEN_LANGS`), `average_wer.py`, `get_wav_res_ref_text.py`.
- **Audio quality:** `score_msr_utmos.py` (MSR-UTMOS parallel MOS predictor;
  `score_wav()` scores one file, batch loop in the module CLI).
- **Prosody:** `score_dswed.py` (pairwise DS-WED across K seed dirs),
  `score_mpm_shuffle_floor.py` (real-to-scrambled MPM span), and
  `score_ttsds_pitch.py` (mean-F0 distribution similarity). Character/s
  distributional distance lives in `scripts/speaking_rate_dist.py`.
- **Shell helpers:** `cal_wer.sh` (WER pipeline wrapper, called by
  `scripts/run_score_wer.sh`), `parse_options.sh` (Kaldi-style `--name value`
  argument parser, sourced by every `run_*.sh` entry point).

## `explorer/`

Stdlib-only HTTP server `serve.py` (`--port`, `--root`) serving the explorer
assets. It reads live build caches first and falls back to `explorer/snapshot/`.
APIs include `/api/snapshot`, `/api/utterances`, `/api/audio`,
`/api/reliability`, `/api/speaking_rate`, and `/api/mpm_dist`. See
`explorer/README.md`.

## `data/` layout (inputs)

Two task families: `zero_shot/` (FLEURS-R) and `zero_shot_voxblink/` (VoxBlink2).

**Standard per-`<task>/<lang>/` layout:**
```
text            # "<uttid> <target_text>"
prompt_text     # "<uttid> <reference_speaker_text>"
prompt_wav.scp  # "<uttid> <path_to_prompt.wav>"
waveform/       # prompt_audio_<N>.wav  (reference speaker prompts)
```
- `zero_shot/` covers 35 languages.
- `zero_shot_voxblink/` covers 20 languages (up to ~1500 prompts/lang — 7 of the
  largest reach 1500, smaller languages take their ceiling, ~17.3k total) plus
  `_stage_a/`; bins are sorted worst→best MSR-UTMOS.

## Output conventions (`results/`, gitignored)

Each leaf dir contains: `wavs/`, `wav.scp`, `wav_res_ref_text.wer[.raw]`,
`spk_simi_scores.txt`, `msr_utmos_scores.txt` + `msr_utmos_mean.txt`, and
optionally `ttsds_pitch.csv`. DS-WED and MPM-span aggregates live in their
dedicated results subtrees. Model generations nest as
`results/<model>/<task>/<lang>/` (`omni_<model>/`, `zonos2_<ckpt>/`, hosted-provider
dirs); the GT/whisper baselines fold the task into the dir name and are flat —
`results/gt_zero_shot/<lang>/`, `results/whisper_zero_shot_voxblink/<lang>/`, etc.
`scripts/results_doc/build_results.py` walks both forms.

## Code organization facts

- **Minimal tests:** `tests/smoke_test.py` (stdlib `unittest`, no GPU/network)
  covers the shared `utils.scp` helpers, the `average_wer` aggregation, the
  wav/text join, and the explorer API. Run: `python tests/smoke_test.py`.
- **`utils/` is a package** (`utils/__init__.py`); `scripts/*.py` reach it with a
  uniform repo-root `sys.path` bootstrap + `from utils.X import ...`.
- **Config is distributed**, not centralized: environment variables (`ASR_*`,
  `OMNI_*`, `ZONOS2_*`, `DECODE_DIR`, `VOXBLINK2_AUDIO_ROOT`), inline bash constants
  (model registries in `run_generate_omni.sh`), and Python literals.
- **Servers are sourced, not run:** `scripts/serve_asr.sh` and
  `scripts/serve_omni.sh` define `start_*_server` / `stop_*_server` functions;
  orchestrator scripts source them and own the PID.

## How to exercise the code

- Inspect tracking: `git ls-files | grep -v ^data/`, `git status --short`.
- Smoke test (no GPU): `python tests/smoke_test.py`.
- Full pipeline (GPU + servers): `source scripts/serve_asr.sh; start_asr_server`,
  then `run_infer_zonos2_eval.sh --task zero_shot --test_set en` against an existing
  `results/` dir.
- Browse results: `python explorer/serve.py --port 8000 --root .`.
